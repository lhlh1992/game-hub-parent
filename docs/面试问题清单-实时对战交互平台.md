# 实时对战交互平台 - 面试问题清单（仅问题）

## 必问率最高的 10 个题目序号

**1, 6, 12, 13, 19, 20, 26, 31, 41, 44**

---

## 一、先打穿“真实性与边界”

1. 你说你是“整体设计与核心开发负责人”，这个项目一共几个人，开发周期多久？
2. 你个人实际写了哪些模块，哪些不是你写的？
3. GitHub 上哪个目录最能体现你的核心贡献？请具体到文件或提交。
4. 这个项目现在是 PoC、Demo、还是可上线系统？你如何定义？
5. 线上真实用户规模是多少？如果没有线上，测试数据规模是多少？

## 二、架构选型合理性（宏观）

6. 为什么这个项目要用微服务，而不是单体？
7. 你用了 WebFlux + WebSocket，为什么要两者都用？分别解决什么问题？
8. 你用了 Kafka，哪些链路必须异步？哪些必须同步？
9. Redis 在这个系统中承载了哪些状态？为什么不只用数据库？
10. 为什么选 PostgreSQL，不是 MySQL 或 MongoDB？
11. Keycloak 放在这个项目里是“必须”还是“可替换”？替换成本有多大？

## 三、并发与一致性（面试官最爱打）

12. 你说“高并发”，那你定义的并发场景是什么？是连接并发、请求并发还是操作并发？
13. 你如何保证“同一局对战”在并发下不会出现双写或状态错乱？
14. 你如何保证房间级隔离，不会串房或跨房污染？
15. 你说有“状态恢复”，恢复过程中如何避免读到脏状态？
16. 断线重连时，客户端和服务端状态冲突怎么裁决？
17. 你如何处理“重复提交”（比如重放消息、重复落子、重复认输）？
18. 你如何证明你的并发控制是正确的？有测试证据吗？

## 四、性能与容量（QPS/在线数硬问题）

19. 你项目现在能支持多少 QPS？这个数是测出来的还是估出来的？
20. 你说能支持多人在线，具体“同时在线人数”是多少？怎么测的？
21. 压测场景是接口压测还是业务流程压测？为什么？
22. 你的压测指标看哪些：P95、P99、错误率、连接数、GC、慢查询？
23. 压测时系统瓶颈先出现在哪：网关、应用、Redis、PG、Kafka？
24. 你怎么做容量规划？如何从当前容量推算到 10 倍流量？
25. 如果并发翻倍，你预计最先崩的是哪一层？你的依据是什么？

## 五、账号与会话治理（简历重点）

26. 你说“单设备在线”，这个“设备”在技术上如何定义？
27. 两台设备同时登录同一账号，最终一致状态是什么？如何保证？
28. 踢线是如何做到端到端可感知的？如果通知丢了怎么办？
29. 会话状态在多服务之间如何同步？一致性模型是什么？
30. token 刷新和会话有效性如何保持一致？有没有竞态窗口？

## 六、房间与状态恢复（简历重点）

31. 你说“服务重启后可恢复已完成房间”，恢复策略是全量扫描还是按需恢复？
32. 恢复时如何保证顺序正确（先房间再对局还是先对局再房间）？
33. 恢复失败时的降级策略是什么？用户看到什么？
34. 你怎么处理恢复过程中的版本兼容（状态结构变更）？
35. 恢复能力是“理论设计”还是“演练验证”？有过故障注入吗？

## 七、事件驱动与可观测性

36. 你把登录/登出/踢线事件化了，那事件幂等怎么做？
37. Kafka 消费失败或重复消费时如何处理？
38. 你如何追踪一条完整链路（用户操作 -> 多服务 -> 最终状态）？
39. 你有没有可观测性体系（metrics、trace、log）？没有的话怎么定位线上问题？
40. 你提“高可靠”，你的 SLO/错误预算是什么？

## 八、工程化与交付可信度

41. 你说工程化落地，有 CI/CD 吗？自动化测试覆盖率多少？
42. 你提“一键启动”，除了能跑起来，还保证了哪些工程质量门槛？
43. 这个项目做过哪些类型的测试：单测、集成、压测、故障演练？
44. 如果今天让你上线生产，你最担心的三个风险是什么？
45. 你下一个版本最优先补哪三件事？为什么不是其他项？

## 九、反向压力题（刁钻追问）

46. 如果我说你这个项目更像“功能堆叠”，而不是“可运营平台”，你怎么反驳？
47. 你提了很多技术名词，哪些是“必须复杂”，哪些其实“过度设计”？
48. 如果不用 Kafka，这个系统还能跑吗？会损失什么？
49. 如果不用 Keycloak，自研 JWT 体系可不可行？你怎么权衡？
50. 你项目里最失败的一次技术决策是什么？你后来怎么修正的？
