# 如何保证不串房间与并发一致性（面试说明）

## 一句话版本

我们用的是 **roomId 全链路隔离 + 状态机约束 + Redis CAS 原子写**。先保证不串房，再保证并发下只成功一次写入。

---

## 1. 如何保证不串房间（基础能力）

我做了四道闸门：

1) **路由隔离**
- 前端订阅和后端广播都绑定 `roomId` 主题（如 `/topic/room.{roomId}`）
- 非本房间消息不会被订阅到

2) **数据隔离**
- Redis 键全部带 `roomId` 前缀
- 房间状态、棋盘状态、座位绑定都按房间分区存储

3) **权限隔离**
- 每个操作先校验用户是否是该房间成员/座位
- 非房间用户不能落子、认输、重开等

4) **写入隔离**
- 所有写操作都必须带 `roomId` 上下文并由服务端校验
- 不信任前端本地状态，前端传错参数也会被服务端拦截

**结论：** 路由、存储、权限、写入四层都按 roomId 约束，基本可以杜绝串房。

---

## 2. 如何保证并发安全（同房间内）

在同一房间里，核心是两层：

1) **状态机约束**
- 房间状态必须合法迁移（如 WAITING -> PLAYING）
- 不在合法状态时，操作直接拒绝

2) **Redis CAS 原子条件更新**
- 落子时带 `expectedStep` 和 `expectedTurn`
- 只有匹配当前状态才允许提交
- 并发冲突时，只会有一个请求成功，其他返回冲突

**结论：** 状态机保证“能不能做”，CAS保证“并发下只成功一次”。

---

## 3. 面试可直接说的 20 秒回答

我们先用 roomId 做全链路隔离，保证消息路由、Redis 键、权限校验和写入上下文都在同一房间内，避免串房。然后在房间内用状态机限制合法操作，再用 Redis CAS 保证同一回合并发写只会成功一次。最终通过 SNAPSHOT 广播把所有客户端收敛到同一状态。
